What it does

Headrouter is a stateless OpenAI-compatible gateway. It accepts /v1/chat/completions requests, optionally compresses the conversation with headroom, then routes to a provider (OpenAI, Anthropic, Gemini, Ollama, OpenRouter, or any OpenAI-compatible endpoint) through named aliases with per-key entitlements.

  • Provider — where requests go (base_url + credential).
  • Alias — a named route, e.g. fast → or:gpt-4o-mini. Clients only send alias names.
  • Key — a downstream credential granted a set of aliases.

Environment variables

All behavior is driven by env vars. Which ones actually reach the gateway depends on how you run it — see Desktop / tray install for the important difference.

VariableDefaultDescription
HOST / PORT0.0.0.0 / 8000Listen address. The tray forces 127.0.0.1.
GATEWAY_API_KEYSemptyComma-separated admin keys (full routing power + access to /admin). Empty disables auth entirely. Scoped keys from providers.json get 403 on admin.
GATEWAY_PROVIDERS_FILEemptyPath to a providers.json (providers/aliases/keys). The desktop launcher defaults this to ~/.config/headrouter/providers.json.
GATEWAY_PROVIDERSemptyInline JSON alternative to the file above.
GATEWAY_ROUTESemptyalias=provider:model,... env-based routing (admin keys only, no JSON needed).
GATEWAY_DEFAULT_ROUTEemptyprovider:model fallback for unrouted models (admin keys).
GATEWAY_ENV_FILE.envEnv file auto-loaded when running from source. The frozen desktop app instead always loads the fixed per-user ~/.config/headrouter/.env.
COMPRESSION_ENABLED1Enable headroom compression. Set 0 to disable.
COMPRESSION_THRESHOLD_TOKENS0Compress only when input exceeds this token budget; 0 = always compress.
COMPRESSION_STRATEGYcodingHeadroom profile: coding (recommended), balanced, general, agent-90 (aggressive), default (legacy router).
COMPRESSION_PREFETCH_ENABLED1Download the ONNX model + tokenizer before accepting requests.
REQUEST_TIMEOUT_SECONDS300Upstream timeout.
OPENAI_API_KEY, ANTHROPIC_API_KEY, GEMINI_API_KEY, OPENROUTER_API_KEYProvider credentials. Referenced from providers.json by name via api_key_env — the secret value lives only in the environment.
*_BASE_URLprovider defaultsOverride provider endpoints (proxies, Azure-style gateways, OLLAMA_BASE_URL).
⚠ Secrets in providers.json

Providers can carry a credential two ways: api_key_env (the name of an env var holding the key — the value stays out of the file) or an inline api_key (the literal secret in the file). Inline values are accepted on disk for local use but are rejected by the admin API, so prefer api_key_env. Either way, if the credential a provider needs isn't resolvable, requests to it fail auth upstream.

Desktop / tray install

When installed from the .deb / .app and launched from the tray icon, the gateway runs as a frozen binary with a crucial difference:

The desktop app does NOT read the repo's .env file

Config and env vars come from the locations below — not from the repo's .env or providers.json.

Where things live

WhatPath
Providers / aliases / keys~/.config/headrouter/providers.json
Environment variables~/.config/headrouter/.env
Gateway log~/.local/state/headrouter/gateway.log

Setting env vars for the tray-launched gateway

Edit ~/.config/headrouter/.env — via tray → Edit environment (creates a commented template on first use) or any text editor — then tray → Restart. No logout needed:

# ~/.config/headrouter/.env
GATEWAY_API_KEYS=hr_...          # admin key for /admin
OPENROUTER_API_KEY=sk-or-...     # credentials for api_key_env entries
# COMPRESSION_STRATEGY=balanced  # optional; default is coding

The file is loaded non-destructively: real environment variables (desktop session, wrapper scripts) always take precedence over it.

First run

  1. Start from the app grid (autostarts at login). The tray icon appears (greyed = stopped, color = running).
  2. An empty config is seeded at ~/.config/headrouter/providers.json.
  3. Tray → Open admin UI, paste your GATEWAY_API_KEYS value, and add providers/aliases/keys there — or copy an existing providers.json into place and tray → Restart.

providers.json

{
  "providers": [
    { "name": "or", "type": "openrouter",
      "base_url": "https://openrouter.ai/api/v1",
      "api_key_env": "OPENROUTER_API_KEY" }
  ],
  "aliases": { "fast": "or:gpt-4o-mini" },
  "keys": [
    { "name": "team-a", "api_key": "key-team-a", "aliases": ["fast"] }
  ]
}
  • providers[].api_key_env — the name of an env var holding the credential (never the value). Alternatively use inline api_key to put the literal secret in the file (local use; rejected by the admin API).
  • aliases — name → "provider:model"; the provider must exist. Use "*" in a key's aliases to grant all current and future aliases.
  • keys — downstream credentials with a non-empty aliases grant list. Resolution is closed: a key can only reach its granted aliases.

Easiest path: manage all of this from the Admin UI (stage → validate → apply, atomic hot reload, no restart).

Pointing clients at it

Any OpenAI-compatible client works. Base URL http://127.0.0.1:8000/v1, API key = a key from your keys list, model = an alias it's granted:

curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Authorization: Bearer key-team-a" \
  -H "Content-Type: application/json" \
  -d '{"model": "fast", "messages": [{"role": "user", "content": "hello"}]}'

GET /v1/models returns the models available to the authenticated key.

Troubleshooting

  • Admin page asks for a key / 403 — set GATEWAY_API_KEYS in ~/.config/headrouter/.env (tray → Edit environment), then tray → Restart; scoped providers.json keys get 403 on admin by design.
  • Provider auth errors — the env var named by api_key_env isn't set in the gateway's environment. Add it to ~/.config/headrouter/.env and tray → Restart.
  • No tray icon on GNOME/Wayland — install/enable the "AppIndicator and KStatusNotifierItem Support" extension.
  • Where are the logs? — tray → Open logs, or ~/.local/state/headrouter/gateway.log.
  • Changes to providers.json not applied — tray → Restart (or use the Admin UI, which applies with no restart).
  • Liveness / metrics — GET /health, GET /metrics.
